# The in-process projection offers no semantics the network projection lacks

A frozen test replays in-process (`PlaytestCase`) what a Scenario did over the network (`dispatch.gd`). Two divergences had settled in: `PlaytestCase` grew a **one-shot assertion** the protocol does not expose (the only assertion verb on the wire is `assert_property`, implemented by sending `wait_for`, so it always retries until timeout), and `start_game()` mounts the game **under the test node** while the live projection mounts it under `get_tree().root`. Decision: **the in-process projection presents no mode the network projection lacks, and mounts the game where the live projection mounts it** — when a semantic is missing on both sides but justified, it is added to both surfaces under the same name, never to only one.

Naming corollary: when two semantics legitimately coexist, **the call site names which one it means** — never the type of an argument. `assert_*` retried or not depending on whether its argument was a `Callable` or an already-evaluated value, both forms being spelled identically and both requiring `await`. The failure mode was silent, intermittent, and looked like a product bug rather than a test-authoring mistake (#35). The two intents now carry two prefixes: `assert_now_*` (value) and `assert_eventually_*` (`Callable`), each rejecting the other's argument; `assert_property` becomes `assert_eventually_property` **on both surfaces** and gains its counterpart `assert_now_property`.

One behavioural asymmetry survives, and becomes legitimate because it is named: `assert_now_*` runs even after a selector failure (constant cost, cannot hang, and several independent failures are worth more than one), whereas `assert_eventually_*` is skipped (nothing to await from a getter referencing an already-broken selector, otherwise `timeout_ms` burned per assertion).

## Considered Options

- **A deprecation path** (keep `assert_*` accepting both forms, with `push_warning` on the value form) — rejected: a `push_warning` in a headless CI log is exactly the silence the ticket denounces, and the ambiguous form stays legal. `godot-playtest-mcp` is not published on npm (#32 open), so the clean break costs no external consumer.
- **Leaving `assert_property` untouched** — rejected: it has no ambiguity to fix (it takes a selector, not a value-or-`Callable`), but a `now`/`eventually` convention that tolerates one exception — "you just have to know that `assert_property` waits" — reintroduces precisely the defect the convention removes. Renaming the wire verb is free until #32 ships, and permanently costly afterwards.
- **A mount option** (`start_game(path, mount_at_root := false)` or an overridable `_mount_root()`, the shape the ticket proposed) — rejected: an option institutionalises the divergence and forces every generated test to pick a side. No frozen test has a legitimate reason to mount the game where a live Scenario never would.

## Consequences

- Mounting goes through `get_tree().root.add_child.call_deferred(...)`: a direct `add_child()` **fails** ("Parent node is busy setting up children") because the runner is still inside its own `_ready()`. Measured cost over the previous mount: **none** — both forms await exactly one process frame, so no existing test's `t0` reading changes. The absolute contract is that `start_game()` returns once `_ready()` has run for the whole mounted subtree but before any `_process()` tick on it; a value that only settles during that first `_process()` needs the eventual form, not a `now` assertion.
- The addon detaches the mounted scene synchronously (`remove_child`) before freeing it. A bare `queue_free()` merely schedules deletion, so the node would still occupy its name under `get_tree().root` when the next `test_*` mounts there, and Godot would auto-rename the new instance — reintroducing the divergence this decision removes.
- The resolution root stays scoped to the mounted game scene rather than following the mount to `get_tree().root`: live, `/root` has only the game as a child, whereas in a frozen run the runner is its sibling. Scoping to the game makes the two surfaces equivalent instead of leaking runner nodes into `query`.
- The addon owns the teardown of what it mounted: freeing the test node no longer cascades to the game.
- The `start_game(scene_path)` signature does not change — the Freeze generator needs no change.
- `docs/protocol/DRAFT-v0.md` §7 must be corrected: its normative rule announces `assert_*` as retry-until-timeout by default, while its own example just above uses the value form, which did not retry — and omits the `await` the implementation requires.
